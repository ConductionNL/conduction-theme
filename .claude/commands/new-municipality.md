## Step 1 — Extract design info from the website

If a website URL was provided, use **Playwright MCP** to visually inspect the municipality website. Follow these steps:

1. **Navigate** to the website URL using Playwright MCP (`mcp__playwright__browser_navigate`).
2. **Take a screenshot** (`mcp__playwright__browser_screenshot`) of the full homepage to get an overview of the visual design.
3. **Inspect the following pages** — navigate to each, take a screenshot, and examine the rendered styles:
   - The **homepage**
   - The **search page** (try `/zoeken`, `/search`, or any visible search page link) — this often reveals input fields, result cards, pagination, and other components
   - **2–3 additional random content pages** (e.g. a news article, a service page, a contact page) to discover more components in context
4. **On each page, examine these UI areas**:
   - **Page header**: logo, navigation bar, background color, text color, font
   - **Page footer**: background color, text color, font, links
   - **Headings (h1–h4)**: font family, font weight, color, size
   - **Body text / paragraphs**: font family, font size, color
   - **Primary buttons**: background color, text color, border-radius, hover state (use `mcp__playwright__browser_hover`)
   - **Secondary buttons / links**: color, underline style
   - **Form inputs / textboxes / search bar**: border color, focus color, border-radius
   - **Cards / panels** (if present): background, border, shadow
   - **Alerts / notifications** (if present): colors per type (error, warning, success, info)
   - **Any other distinct UI components** visible on the page
5. **Extract the following values** from your visual inspection and computed styles (`mcp__playwright__browser_evaluate`):
   - Primary brand color (hex)
   - Primary hover color (hex, slightly darker)
   - Heading font family name and weight
   - Body font family name
   - Any secondary/accent colors used
   - **Per-component styles** — for every component area found on any of the pages visited, use `mcp__playwright__browser_evaluate` to read the computed CSS. Capture everything needed to replicate the component with tokens: `background-color`, `color`, `font-size`, `font-weight`, `border-color`, `border-radius`, `padding-block`, `padding-inline`, `margin-block`, `outline-color` on focus, hover state colors, etc. Record these for every component you encounter — the more complete, the better.
   - **Paragraph font size** — note the exact `font-size` in px used on `<p>` tags. Convert to rem (÷16). This will calibrate `md` in `font-size.tokens.json`.
6. **Find font files**: Use `mcp__playwright__browser_evaluate` to inspect `document.fonts`, look in the browser's loaded resources for `.woff`, `.woff2`, `.ttf`, or `.otf` files, and check `<link>` tags for Google Fonts URLs. Font files are often under the site's own `/fonts/` or `/assets/fonts/` path. Note all font file URLs found — you will download them in Step 2.

If no URL was provided, use placeholder values (noted below) and inform the user they should update the color and font values.

#### Color naming convention

**Lightness percentage** — The number in a color key represents the lightness/darkness of that color as determined by the [W3Schools color picker](https://www.w3schools.com/colors/colors_picker.asp). Enter the hex value and read the percentage from the Lighter/Darker scale:

- `#ffffff` (white) = `100`
- `#000000` (black) = `0`
- `#808080` (mid grey) = `50`
- `#012c9d` (dark blue) = `31`

So a color group key like `"31"` means that color sits at 31% on the lightness scale.

**Transparency suffix** — When a color has opacity, append `-{n}t` to the key where `{n}` is the opacity percentage. The hex value gets a 2-digit alpha suffix appended:

| Opacity | Hex suffix                 |
| ------- | -------------------------- |
| 100%    | `FF` (omit — fully opaque) |
| 80%     | `CC`                       |
| 60%     | `99`                       |
| 50%     | `80`                       |
| 10%     | `1A`                       |

Full reference: https://gist.github.com/lopspower/03fb1cc0ac9f32ef38f4

Example: `#012c9d` at 10% opacity → key `"31-10t"`, value `"#012c9d1a"`

Only add transparency variants when they are actually used on the municipality website.

**Color palette ordering inside the `color` object:**
1. Semantic aliases (`primary`, `primary-hover`, `error`, alert variants, etc.)
2. Brand-specific palette groups from the website (e.g. `blue`, `green`, `red`, `yellow`) — ordered lightest group last
3. `grey` (full baseline)
4. `lightgrey` (if present — sits between grey and white)
5. `white` (full baseline)
6. `black` (full baseline)

Set the values based on the computed font sizes extracted from the website in Step 1. The mapping between font-size keys and components is:

| Key   | Used by component      |
| ----- | ---------------------- |
| `md`  | `paragraph`, `heading-5` — **set to the most-used paragraph font-size on the website** |
| `lg`  | `heading-4`            |
| `xl`  | `heading-3`            |
| `2xl` | `heading-2`            |
| `3xl` | `heading-1`            |

Extract the computed `font-size` of `<p>`, `<h1>`, `<h2>`, `<h3>`, `<h4>` from the website and set the corresponding keys. Convert px values to rem (divide by 16). If you find additional distinct sizes used on the website (e.g. for captions, labels, small text), map them to the nearest smaller key.

### Update component tokens to match the website

After all component files are written, go through **every** component token file and update its token values to replicate the visual appearance on the municipality website as closely as possible.

**For each component file:**

1. Read the token file.
2. Find the matching component on the website (using the Playwright MCP screenshots and computed styles from Step 1).
3. For every token property (background-color, color, font-size, font-weight, border-color, border-radius, padding-block, padding-inline, margin, outline, etc.) — if the website shows a different value than what is currently in the file, update it.
4. Always prefer referencing an existing palette token (e.g. `{<slug>.color.black.0}`) over hardcoding a hex value. Only use a literal hex if the color is not in the palette — in that case, add it to the palette first.
5. Also update `font-size.tokens.json` keys to match heading and paragraph sizes found on the website:
   - `md` → paragraph / h5 font-size
   - `lg` → h4 font-size
   - `xl` → h3 font-size
   - `2xl` → h2 font-size
   - `3xl` → h1 font-size
   - If you find other sizes (captions, labels, etc.) map them to the nearest smaller key.

**If you did not find a matching component on the website** for a given token file, leave that file's token values as they are (the conduction defaults will apply). Do not leave tokens empty that had values — only change values where you have observed a real difference on the website.
